# 家庭 iOS App 管家

**让自己写的 App，从开发工具走进家人的日常。**

给孩子做的练习工具、给家里电视写的遥控器，往往只需要装在几台自己的设备上。但开发完成之后，还有安装、七天续签、换机、存档迁移和桌面入口这些小事。

这个 skill 把它们整理成一套 Agent 可以接手的流程。基于 **AltStore Classic + AltServer + LiveContainer**，帮助你把自制 App 装进 iPhone 和 iPad，保留已有记录，并完成后续维护。

[查看 Agent 执行说明](SKILL.md) · [返回 Skills 索引](../README.md)

## 它能帮你做什么

### 新设备接入，沿用已有成果

先识别设备、账号签名与现有安装，再补上缺少的部分。不因为换了一台手机，就把另一台已经跑通的流程全部重做。

### 把 App 和记录一起带过去

处理安装包、备份原有资料、找到正确的数据容器，再读回核对。关注的不只是“能打开”，还有原本的题目进度、历史记录和本机设置是否还在。

### 在家刷新，继续使用

配置 Mac 与设备的 Wi-Fi 连接，完成真正的拔线刷新测试。之后通过手机或平板上的 AltStore 发起刷新，不用给每个容器内 App 单独续签。

### 桌面入口，名字和图片都对得上

生成使用官方 Launch App 动作的直启捷径。下载页同时提供 App 名称、原图预览、捷径文件和图片文件，减少复制网址、寻找图标的操作。

## 适合这样的你

- 自己开发一些家庭使用的 iPhone / iPad App。
- 使用免费 Apple 开发签名，接受定期刷新。
- 家里有一台 Mac，愿意让它运行 AltServer。
- 希望让 Agent 处理技术准备，只在必要时亲自完成设备确认。

默认采用家庭 Wi-Fi 和本机 Mac，不需要在手机上额外安装 VPN。它使用你自己的 Apple 账号签名，不依赖购买第三方签名服务。

## 一次接入，大致会经历什么

**确认设备 → 备份资料 → 安装容器 → 导入并首次启动 App → 迁移记录 → 创建直启捷径 → 拔线验证刷新**

如果安装遇到网络问题，有官方 IPA 的本地安装路径；如果 USB 能用、Wi-Fi 不行，会先检查 Finder 设置与实际无线设备发现，而不是让你反复重装。

这些步骤来自 iPhone 与 iPad 的实际接入经验，包括下载超时、App ID 额度不足、首次启动与无线刷新等问题。遇到新的环境，Agent 仍需重新验证。

## 交给 Agent 的方式

首次设置设备：

> 使用 `$ios-home-sideload`，帮我给这台 iPad 配置 AltStore 和 LiveContainer，保留原有 App 记录，并完成无线刷新和桌面捷径。

增加一个 App：

> 使用 `$ios-home-sideload`，把这个自制 App 加入现有容器。先备份，不重做已经正常工作的账号和设备设置。

执行入口是 [SKILL.md](SKILL.md)。需要本地安装时，将当前目录链接到 Agent 的技能目录；Codex 示例：

```sh
# 在仓库根目录执行；若目标已存在，先比较，不直接覆盖。
mkdir -p ~/.codex/skills
ln -s "$PWD/ios-home-sideload" ~/.codex/skills/ios-home-sideload
```

## 使用前，知道这些就够了

- **免费签名仍需定期刷新。** 刷新时 Mac 要开机、登录、运行 AltServer，并能连接 Apple 服务；设备与 Mac 需要互相可达。
- **桌面图标还需要最后一次手动设置。** 直启捷径能省去 Safari 入口，但选择原图、确认“加入主屏幕”仍由你在设备上完成。
- **容器不是多个独立安装的 App。** 切换应用时可能需要结束当前应用，兼容性也需要逐个验证。
- **数据同步由 App 自己决定。** 这个 skill 负责备份和迁移，不会自动让不同设备共享所有进度。

实际设备信息和备份保存在使用者自己的环境中，公开内容只包含流程和工具。
